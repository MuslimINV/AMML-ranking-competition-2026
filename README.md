# AMML 2026 · Ранжирование русскоязычных фрагментов

**Муслим Магомедов · РАНХиГС · команда Kaggle `MuslimINV`**

Модель Giga-Embeddings-instruct-3B-0826 с адаптером LoRA получила **0,951138 NDCG@10** на 392 публичных запросах. Предыдущий ансамбль с DiTy и Qwen получил **0,894592** на тех же запросах. Прирост составил **0,056546**, вторая отправка заняла **25-е место** на момент замера. Итоговую оценку соревнования определяют остальные 913 запросов Private Leaderboard.

Модель обучалась на конкурсных парах «запрос — фрагмент». Для каждого запроса мы сравнивали релевантные фрагменты с кандидатами, которым разметка присвоила ноль. На 608 отложенных запросах исходная Giga получила **0,944668**, после 306 шагов попарного обучения — **0,950508**. В итоговую отправку вошли оценки дообученной модели с весом 1,0. Исходный запуск на двух Tesla T4 занял **2 часа 45 минут** и сформировал оценки для всех 13 507 тестовых строк.

Идею использовать Giga с LoRA подсказал пример другого участника. Для этой работы мы реализовали попарное обучение, проверили метрику на отложенных запросах и разобрали ошибки на уровне отдельных фрагментов.

## Что именно ранжируется

У каждого запроса есть конечный список фрагментов. Каждой строке теста требуется числовая оценка `prediction`. Чем выше оценка внутри своего `query_id`, тем ближе фрагмент к началу выдачи. Масштаб оценок у разных запросов может отличаться. Поиск ведётся среди всех предоставленных кандидатов, дополнительные документы не добавляются.

Официальная метрика — среднее **NDCG@10 по запросам**. Внутри запроса фрагменты сортируются по убыванию `prediction`, при равенстве — по строковому `id` по возрастанию. Если на позиции $r$ находится фрагмент с меткой $y_r$, его вклад в DCG равен $(2^{y_r}-1)/\log_2(r+1)$. Суммируются первые $\min(10,n_q)$ позиций. Для IDCG исходный полный список сортируется по истинной релевантности. При IDCG = 0 запрос получает 0. Затем значения усредняются с одинаковым весом для каждого запроса.

Здесь метки бинарные. Например, если у запроса один правильный фрагмент, первое место даёт NDCG = 1, второе — около 0,631, десятое — около 0,289. Перестановка двух подходящих ответов не меняет метрику. По этой причине в обучении сравниваются именно пары с разными метками.

## Как менялось качество

В первой версии мы ранжировали готовый список фрагментов с помощью лексических признаков и русскоязычного кросс-энкодера DiTy. Для каждого запроса модель должна была поставить выше фрагмент, содержащий ответ. Мы последовательно проверили, помогает ли обучаемому ранкеру оценка DiTy, затем добавили оценки Qwen3-Reranker-0.6B. В таблице показан результат ансамбля после подбора весов по предсказаниям на отложенных фолдах. OOF (out-of-fold) означает, что для каждой строки взят прогноз модели, в обучающую часть которой запрос не входил. Набор запросов во всех трёх строках один и тот же.

| Эксперимент первой версии | Фолды | OOF NDCG@10 | Что изменилось |
|---|---|---:|---|
| Бустинг и разреженная линейная модель вместе с исходной оценкой DiTy | 0–4 | 0,858670 | В ансамбле вес исходной оценки DiTy составил 0,60. |
| CatBoost YetiRank получил оценку DiTy как дополнительный признак | 0–4 | 0,864921 | Вес нового ранкера составил 0,60, выигрыш ансамбля после повторного подбора весов составил 0,006251. |
| К DiTy добавили оценки Qwen3-Reranker-0.6B | 0–4 | 0,898441 | Ранкер с признаками обеих моделей получил вес 0,75. Метрика ансамбля выросла ещё на 0,033520. |

Затем мы дообучили восемь последних слоёв DiTy на разметке конкурса, по две эпохи на фолд. Каждый завершённый фолд занял 40,7–40,8 минуты. После двух готовых фолдов ансамбль получил 0,907808, после трёх — 0,908108, после четырёх — 0,905696 на 2 434 отложенных запросах. Состав запросов и веса ансамбля менялись при каждом пересчёте, поэтому разности между этими тремя значениями нельзя использовать для оценки эффекта дообучения. На пятом фолде закончился бюджет времени. Через 570 минут первая версия сохранила 13 507 предсказаний. Её результат на Public Leaderboard составил **0,894592**.

Для следующей версии мы выбрали Giga-Embeddings-instruct-3B-0826. Замороженная модель задаёт исходный порядок кандидатов по близости эмбеддингов. Попарное дообучение LoRA учит модель присваивать более высокую оценку размеченному положительному фрагменту по сравнению с отрицательным для того же запроса. Качество всех вариантов ниже измерено на одном отложенном фолде из 608 запросов и 6 306 пар.

| Вариант второй версии | NDCG@10 на отложенном фолде |
|---|---:|

На шаге 306 прирост относительно замороженной модели составил **0,005840**, относительно лексической — **0,144402**. По этому фолду выбраны и веса, и контрольная точка. Для замороженной Giga сохранилась лишь средняя метрика, поэтому установить, у скольких отдельных запросов дообучение улучшило или ухудшило порядок, по этим артефактам нельзя.

Итог соревнования определяется на остальных 913 запросах Private Leaderboard.

Результаты первой версии зафиксированы в журнале Kaggle, строки 179, 187 и 292 для пяти фолдов, 297, 302 и 307 для двух, трёх и четырёх фолдов, 309 для остановки обучения и 3119 для сохранения файла. По всем запросам их число меняется от 1 до 10. Поэтому при обучении на парах важно брать кандидатов с проверенной нулевой меткой. Случайный сосед правильного ответа может сам оказаться правильным.

S0 даёт около половины обеих выборок. Доля самого редкого источника S3 возрастает с 7,1% до 8,2%. Разброс доли положительных меток по четырём источникам train составляет около 1,5 процентного пункта. Принадлежность к источнику даёт мало информации о релевантности сама по себе.

## Валидация и проверка пересечений

У валидации та же единица оценки, что и у конкурса — целиком ранжированный запрос. Для разбиения код объединяет запросы в компоненты связности по общему `document_id`, нормализованному тексту вопроса или фрагмента. `GroupKFold(5)` распределяет компоненты по фолдам. Фолд 0 содержит 608 запросов, 6 306 строк и 1 724 положительные метки. Остальные фолды вместе содержат 2 434 запроса, 25 224 строки и 6 444 положительные метки.

|---|---:|---:|
| Идентификатор строки | 0 | 0 |
| Идентификатор запроса | 0 | 0 |
| Нормализованный текст вопроса | 0 | 0 |

Разные фрагменты одной статьи могут встретиться по обе стороны разбиения. Это свойство наблюдается и в конкурсном тесте. Проверка касается точного совпадения после нормализации. Близкие по смыслу переформулировки могут оставаться в разных частях.

В обучающей части 1 574 из 2 434 запросов (64,7%) имеют несколько правильных фрагментов. У 6 886 из 18 780 отрицательных пар (36,7%) статья совпадает со статьёй хотя бы одного правильного ответа на тот же запрос. Эти отрицательные примеры позволяют сравнить соседние материалы на одну тему, когда совпадение заголовка уже не помогает.

## Как из CSV получается прогноз

### Очистка и контроль идентификаторов

Одна строка — один кандидат внутри запроса. Поле `id` используется для сопоставления с образцом. `query_id` объединяет выдачу, `document_id` участвует в группировке для валидации, `article_id` связывает фрагменты статьи. Строковое чтение сохраняет исходные ключи. Проверяются уникальность `id`, непересечение идентификаторов train и test, равенство множеств `id` теста и образца, наличие обязательных полей и бинарность обучающих меток.

Текст дважды декодируется из HTML-сущностей. Удаляются несколько известных тегов и навигационных шаблонов по краям строки, невидимые разделители и мягкие переносы. Нормализуются Unicode и пробелы. Из заголовка убирается стандартный суффикс «Википедия». Отсутствующий заголовок заполняется только тогда, когда в пределах данной статьи и данного запроса встречается единственный известный вариант. Признаки сырого форматирования рассчитываются отдельно от очищенного текста. Для нейросети сохраняются регистр и пунктуация, а для поиска совпадений используется отдельная нормализация.

### Лексический и структурный прогноз

| Группа | Примеры признаков | Какой случай помогает распознать |
|---|---|---|
| Термины запроса | Покрытие точных слов и упрощённых основ, редкость совпавшего термина, BM25 с удвоенным вкладом заголовка | Кандидат совпадает с редким именем, годом или названием |
| Положение совпадений | Первое совпадение, порядок пар слов, лучшее окно в 16 и 48 слов, начало фрагмента | Слова запроса сосредоточены в одном месте и могут образовывать ответ |
| Структура документа | Положение фрагмента, доля пройденной статьи, соседние фрагменты, длины заголовка и текста | В выдаче несколько похожих абзацев одной статьи |
| Статистика внутри выдачи | Ранг признака, отставание от лучшего кандидата, среднее по статье | Одинаковое абсолютное число совпадений может соответствовать разным местам в двух выдачах |
| Форма текста и запроса | Числа, годы, слова «когда», «сколько», «где», признак отсутствующего заголовка и следы разметки | Вопрос о дате отличается от вопроса об определении |

`HistGradientBoostingClassifier` обучается на конкурсных метках обучающей части. Параметры — 200 итераций, до 23 листьев, минимальный лист 35, скорость обучения 0,065, L2 = 3, seed 1949. В качестве оценки используется `decision_function`. Признаки относительно других кандидатов доступны и для новых запросов, поскольку на вход подаётся весь список. Лексическая модель даёт базовую линию качества и способ находить нерелевантные фрагменты, которые внешне похожи на ответ.

### Представление запроса и фрагмента

Основа — опубликованный двунаправленный энкодер `ai-sage/Giga-Embeddings-instruct-3B-0826`, зафиксированная ревизия `b71168088212f0a13688514e4fc288a86106c4e4`. К запросу добавляется инструкция «Найди фрагмент текста, который отвечает на поисковый запрос». Кандидат подаётся как заголовок, перенос строки и текст фрагмента. Один энкодер строит оба представления. Для каждого текста берётся среднее по выходам реальных токенов с учётом маски, затем вектор нормируется по L2. Скалярное произведение двух единичных векторов даёт косинусное сходство. Предел — 512 токенов на текст. Длинный фрагмент может потерять ответ, если он расположен за границей усечения.

Запрос кодируется один раз для его кандидатов в пределах вычислительного процесса. Одинаковые тексты при инференсе также допускают повторное использование эмбеддинга. Это позволяет оценить весь список кандидатов за ограниченное время. Базовые веса загружаются из публичного релиза модели. Обучающие пары строятся исключительно из конкурсного `train.csv`. Внешний размеченный корпус, внешние негативы и тестовые метки в дообучении не используются.

### Как устроено дообучение на метках конкурса

1. Для каждого обучающего запроса берутся до двух разных релевантных фрагментов. В следующем проходе список положительных сдвигается, чтобы запрос с тремя и более ответами мог показать модели другие фрагменты.
2. Отрицательные берутся только среди фрагментов этого же запроса с `relevance=0`. Дубли по текстовому представлению удаляются. Если текст совпал с любым положительным фрагментом запроса, он исключается из отрицательных.
3. При наличии кандидатов из статьи одного из выбранных правильных фрагментов берётся самый сложный из них. Затем берётся оставшийся кандидат с наибольшей оценкой сложности. Свободные места до трёх заполняются из остальных кандидатов с фиксированным генератором. Поэтому обучение включает и близкие по теме абзацы, и более простые различия.
4. Для запроса строятся все пары «положительный — отрицательный» среди выбранных фрагментов. Пусть $s_+$ и $s_-$ — их косинусные сходства с запросом. Функция потерь одной пары равна $\log(1+\exp((s_- - s_+)/0{,}05))$. Перестановка, при которой нерелевантный абзац выше правильного, увеличивает штраф. Потери усредняются внутри запроса. Длинные списки кандидатов получают сопоставимый вес с короткими.
5. Базовые веса энкодера заморожены. В проекциях внимания `q_proj` и `v_proj` всех 36 слоёв обучаются адаптеры LoRA с рангом 8 и `alpha=16`. Обновляются 2 064 384 параметра. Оптимизатор — AdamW, пиковый learning rate $5\cdot10^{-5}$, weight decay 0,01, ограничение нормы градиента 1. На втором проходе скорость умножается на 0,70.
6. Исходный расчёт рассчитан на две T4, по одному процессу на GPU. В полном шаге накапливается до 8 групп на каждом устройстве, затем градиенты усредняются. Основные веса и вычисления на T4 используют FP16, обучаемые параметры LoRA хранятся в FP32. Для экономии памяти эмбеддинги группы сначала рассчитываются без графа, после чего градиент по эмбеддингам передаётся повторным прямым проходом короткими блоками. Это позволяет сравнивать несколько фрагментов одного запроса, сохраняя в GPU-памяти ограниченное число активаций.


Время выбора сложных примеров было ограничено. Исходный код сначала измерял длительность проходов замороженного энкодера. При достаточном остатке бюджета сложность рассчитывалась по смеси 75% стандартизированной оценки Giga и 25% лексической оценки. При нехватке времени использовалась лексическая оценка. Правило выбора примеров из той же статьи действовало в обоих случаях. Финальный отчёт сохранил веса для прогноза и шаг обучения. Ветвь отбора примеров в нём отдельно не отмечена, поэтому при повторном обучении ноутбук применяет исходное правило по замеренному времени. Для точного восстановления обученных параметров доступен сам адаптер конкурсного запуска.

### Оценки компонентов

Для объединения разных сигналов оценка каждого компонента центрируется по среднему и делится на стандартное отклонение внутри запроса (`ddof=0`). При нулевом разбросе знаменатель принимается равным единице. Это сохраняет порядок у одного компонента и позволяет складывать оценки разного масштаба. Итоговый файл содержит `id,prediction` для всех кандидатов в порядке `sample_submission.csv`. Отрицательные значения допустимы, поскольку задача использует порядок оценок.

В исходном эксперименте рассматривались лексический прогноз, исходный Giga и Giga с обученным адаптером. Для базового Giga проверялась примесь лексического компонента 5% или 20%. При наличии адаптера проверялись полный вес семантической части у дообученного энкодера или её разделение поровну с исходным Giga, с 0% или 10% лексического компонента. Вес выбирался по NDCG@10 на тех же отложенных запросах. Та же метрика использовалась для выбора конфигурации. Независимый публичный результат вычислил Kaggle. В зафиксированном решении остался один компонент — стандартизированные оценки дообученной Giga с шага 306.

## Интерпретация результата

- **Что дало дообучение.** Оценка замороженной Giga и её адаптера получена на одних и тех же 608 запросах. После 306 шагов NDCG@10 вырос с 0,944668 до 0,950508. Это наблюдаемый прирост **0,005840** на фолде, который служил и для выбора шага. Для замороженной модели в журнале сохранилась только средняя оценка. Проверить распределение этого прироста по запросам или оценить его неопределённость парным сравнением по имеющимся результатам невозможно.
- **Где остаются ошибки.** Построчные валидационные прогнозы финальной Giga позволяют проверить каждый запрос. Относительно обученной лексической модели её NDCG@10 выше на 371 запросе, ниже на 62 и совпадает на 175. Для 51 запроса Giga поставила на первое место нерелевантный фрагмент. В 24 из этих 51 случаев выбранная статья содержала релевантный фрагмент для того же запроса. Выбор конкретного абзаца внутри статьи остаётся измеримой проблемой.
- **На какие запросы распространяется вывод.** Обучающая часть содержала 2 434 запроса, отложенная — 608. Разбиение сохраняло вместе запросы, связанные общим документом, нормализованным текстом вопроса или фрагмента. В одном компоненте связности оказалось 437 из 608 валидационных запросов. Преимущество финальной Giga над лексическим бустингом наблюдается как в этом компоненте (+0,149395), так и среди оставшихся 171 запроса (+0,131643). Один фолд с такой концентрацией даёт ограниченную оценку вариативности на новых наборах запросов.
- **Что показывает публичная отправка.** Разница **+0,056546** между первой и второй версиями характеризует полную замену пайплайна на одних и тех же 392 запросах. Публичный балл финальной модели выше локального на 0,000630. Выборки содержат разные запросы, а итоговая оценка на остальных 913 запросах остаётся скрытой. При переходе от исходной Giga к дообученной мы одновременно задали попарную функцию потерь и способ выбора отрицательных примеров. Для оценки вклада именно сложных отрицательных фрагментов нужен отдельный запуск с тем же разбиением, оптимизатором и числом шагов, в котором меняется только выбор отрицательных примеров.
